# Content Guidelines

## Purpose

This file defines the non-negotiable content rules of the Hanuja marketplace.

It exists to keep content quality and content behavior consistent across:

- product titles
- product descriptions
- category texts
- store page content
- editorial/blog content
- seller-provided content
- admin-reviewed content
- moderation decisions
- SEO-facing text structures
- customer-visible trust language

If implementation conflicts with this file, this file wins unless a newer approved content decision replaces it.

## Core Content Principle

Hanuja content must feel:

- clear
- trustworthy
- curated
- useful
- commercially strong
- human-readable
- consistent with the brand

Content must never feel:

- spammy
- chaotic
- keyword-stuffed
- generic marketplace filler
- misleading
- legally risky
- low-trust

The platform should favor quality over content volume.

## Content Priority Order

When content decisions conflict, use this priority:

1. factual correctness
2. clarity
3. trust
4. consistency
5. SEO usefulness
6. conversion support
7. stylistic elegance
8. seller convenience

Never improve SEO or conversion by using misleading content.

## Content Ownership Principle

Content may come from different sources, but the platform must still govern quality.

Possible content origins include:

- seller-entered content
- admin-edited content
- platform-generated helper content
- editorial/blog content
- structured content templates
- migration/import content

Regardless of source, the final customer-visible content must follow Hanuja standards.

## Core Content Types

Hanuja content should be treated in distinct groups.

### 1. Product content
Includes:

- product title
- short description
- full description
- material details
- dimensions
- care/use notes
- shipping notes where appropriate
- variation text
- media captions if used

### 2. Category content
Includes:

- category intro text
- subcategory guidance
- landing page text
- merchandising copy
- navigation-support text

### 3. Store content
Includes:

- seller/store name
- store bio
- store story
- craftsmanship/process notes
- public trust/profile fields

### 4. Editorial content
Includes:

- blog articles
- buying guides
- decorating guides
- inspiration pages
- trend or care content

### 5. System content
Includes:

- empty states
- alerts
- operational messages
- seller/admin helper text
- moderation messages
- trust/support content

Each content type should follow the same quality philosophy but not the exact same writing style.

## Product Content Rules

Product content is one of Hanuja’s most important trust and conversion surfaces.

### Product title rules

Product titles should be:

- specific
- readable
- commercially useful
- distinct enough from nearby products
- aligned with actual product identity

Product titles should not be:

- stuffed with excessive keywords
- written in all caps
- overloaded with symbols
- vague or generic
- misleading about material, size, or function

### Good product title behavior

A good title should help the customer quickly understand:

- what the product is
- what makes it distinctive
- its essential material/style/type if relevant

### Product description rules

Product descriptions should:

- explain the product clearly
- support real buying decisions
- reflect visible product reality
- help the customer understand use, feel, and fit in context
- avoid shallow repetition

Descriptions should not:

- be copied blindly from other listings
- overpromise quality or availability
- use exaggerated trust-damaging language
- become keyword dumps

### Product detail structure

Where possible, product content should separate:

- summary / key value
- material and production details
- dimensions and technical details
- use/care guidance
- delivery/production notes if appropriate

Do not force all product information into one unstructured paragraph.

## Product Attribute Content Rules

Structured product data and descriptive text must align.

### Rules

- visible attributes must match stored attributes
- material names must be consistent
- dimensions must be formatted consistently
- variant labels must be clear
- avoid conflicting content between structured fields and prose

Do not let description text say one thing while product attributes say another.

## Product Uniqueness Rules

Marketplace content often risks duplication.
Hanuja should actively reduce that.

### Rules

- near-identical products should not reuse the exact same text blindly
- sellers should not flood the catalog with tiny-variation duplicate copy
- platform-assisted content should still preserve uniqueness
- duplicate-title and duplicate-description patterns should be reviewable

Not every product needs literary uniqueness, but indexable product content should not feel mechanically cloned.

## Category Content Rules

Category content should support both SEO and user orientation.

### Category text should:

- explain what the category contains
- reflect real search intent
- help users navigate choices
- remain concise and useful
- avoid filler blocks added only to “have text”

### Category text should not:

- repeat the category name unnaturally
- restate obvious UI labels
- become blog-like when commercial guidance is needed
- be copied across many categories with tiny edits

Category content must feel intentional, not mass-generated.

## Store Page Content Rules

Store pages represent seller identity and trust.

### Store content should:

- describe the seller meaningfully
- support trust
- reflect craftsmanship, product focus, or design identity where relevant
- avoid vague generic brand fluff

### Store content should not:

- contain unverifiable claims presented as fact
- impersonate platform authority
- overuse luxury clichés
- become an SEO spam area

Store content must be seller-safe, customer-trustworthy, and brand-aligned.

## Editorial / Blog Content Rules

Editorial content should help discovery and trust, not just fill a blog feed.

### Good editorial content should:

- answer a real question
- support a real inspiration or buying intent
- be structured and readable
- use clear headings
- connect naturally to product/category/store discovery
- feel useful even without immediate purchase

### Editorial content should not:

- exist only to target keywords with no user value
- copy product/category content
- use shallow repetitive AI filler
- make unsupported authority claims
- drift away from Hanuja’s product universe without reason

## Tone of Voice Rules

Hanuja tone should be:

- warm
- calm
- confident
- clear
- premium through restraint
- helpful, not pushy

### Do

- write naturally
- prefer specific words over generic hype
- sound curated rather than mass-market noisy
- support trust through clarity

### Do not

- shout
- use excessive exclamation
- use cheap urgency language everywhere
- overuse sales clichés
- use robotic wording
- sound legalistic in customer-facing commercial copy unless necessary

## Turkish Language Rules

Primary public language is Turkish unless a multi-language expansion is explicitly supported.

### Rules

- public-facing Turkish should be natural and correct
- avoid mixing Turkish and English carelessly
- use consistent terminology for commerce and product concepts
- do not create artificial or awkward translations for simple concepts
- keep terminology consistent across storefront, seller panel, and admin guidance where appropriate

## Terminology Consistency Rules

Core concepts must be named consistently.

Examples include:

- sipariş
- teslim edildi
- teslim onaylandı
- iade
- uyuşmazlık / ihtilaf if used
- hakediş
- bloke
- ceza
- mağaza
- ürün
- kategori

Do not use several different labels for the same business concept across the system without reason.

## Truthfulness Rules

Content must not make claims that the platform or seller cannot support.

### Do not make unsupported claims such as:

- guaranteed fastest delivery
- best quality in Turkey
- official medical/technical certification without proof
- handcrafted if it is not actually handcrafted
- limited stock claims if system does not support it
- eco / sustainable / organic claims without basis
- platform guarantees that are not operationally real

Truthfulness is mandatory for trust and legal safety.

## Risky Claim Rules

The following kinds of claims should be treated as higher-risk and may require moderation or templates:

- health-related claims
- child-safety claims
- fire/waterproof claims
- certification/guarantee claims
- origin/authenticity claims
- premium material claims
- exaggerated discount claims
- warranty promises
- legal compliance claims

Do not let risky claims pass casually into public content.

## SEO Content Rules

Content should support SEO, but SEO should not degrade quality.

### Rules

- use natural keyword placement
- keep headings meaningful
- avoid keyword stuffing
- align copy with page intent
- ensure product, category, and editorial content serve different purposes
- keep slug/title/metadata/content aligned conceptually

### Do not

- repeat exact keywords unnaturally
- generate many pages with near-identical text blocks
- create bloated paragraphs just to rank
- let SEO content contradict visible UI or structured data

## Heading Structure Rules

Content should use clean heading logic.

### Rules

- one clear H1 per page intent
- subheadings should reflect real structure
- headings should help scanning
- avoid decorative heading usage with no structural value
- do not stack many headings with no meaningful text beneath them

## Short vs Long Content Rules

Not every page needs long text.

### Rules

- use as much content as the page needs, not more
- product pages need useful detail, not forced essays
- category pages need intent support, not filler walls of text
- store pages need trustful identity, not overlong autobiography
- editorial pages may be longer only when value justifies length

Avoid content inflation.

## AI-Assisted Content Rules

AI-assisted content may help, but it must remain reviewed and controlled.

### Rules

- AI content must still meet platform truthfulness rules
- AI output must be edited when needed for clarity and brand fit
- AI should not invent facts
- AI should not create fake craftsmanship stories or fake material details
- AI should not create fake reviews, fake social proof, or fake urgency
- repeated AI-generated templates must be checked for duplication and blandness

AI is an assistant, not a license for low-quality volume.

## Seller-Entered Content Moderation Rules

Seller content should be accepted only if it respects platform standards.

### Seller content should be reviewable for:

- prohibited claims
- misleading wording
- offensive language
- spammy keyword use
- duplicate flooding
- policy violations
- poor-quality store presentation
- category mismatch language
- irrelevant content blocks

The platform should be able to request correction, suppress, or reject content when needed.

## Content Moderation State Rules

Content-related moderation should be explicit where supported.

Useful states may include:

- draft
- submitted
- approved
- needs_revision
- rejected
- hidden
- archived

Do not rely only on informal notes to explain content status.

## Content Revision Rules

Important public content changes should be trackable.

### Trackable areas may include

- product title changes
- store slug/display name changes
- major store bio edits
- category text changes
- editorial publication edits
- moderation-related text decisions

High-impact public content should not change invisibly when traceability matters.

## Image and Media Text Rules

Text associated with media should follow quality rules too.

### Rules

- alt text should be descriptive and useful, not stuffed
- image captions should add value only when needed
- filenames should not be treated as public SEO content strategy by themselves
- media text must not misrepresent the product

## Brand and Style Consistency Rules

Hanuja is a curated platform, so public copy must feel like it belongs to one ecosystem even if different sellers contribute content.

### Rules

- preserve seller uniqueness without breaking platform trust tone
- keep system-generated or admin-generated copy brand-consistent
- avoid extreme tone differences across public surfaces
- use template guidance where consistency matters

## Content Safety Rules

Public content must not include:

- hate or degrading language
- explicit harassment
- illegal promotion
- deceptive sales language
- fake testimonials presented as real
- secret internal notes
- admin-only reasoning
- private personal information not meant for public display

Seller/admin/system content boundaries must remain clear.

## Operational Message Rules

System and operational content must be clear and unambiguous.

This includes messages for:

- payment confirmation
- shipment updates
- delay warnings
- return requests
- payout blocks
- penalty visibility
- moderation results
- admin review outcomes where seller-facing

Operational messages should prioritize clarity over brand flourish.

## Empty and Placeholder Content Rules

Placeholder content must not leak into production.

### Rules

- no lorem ipsum in public pages
- no “test product” style production content
- no empty boilerplate sections that pretend to be real
- no indexable thin placeholders

If content is incomplete, use proper draft/review/unpublished handling.

## Content and Structured Data Alignment Rules

Public content must align with metadata and structured data.

### Rules

- title and visible title should not conflict in meaning
- description should not contradict structured product data
- availability and promise language should align with actual state
- store/product/category identity should stay consistent across visible and machine-readable layers

## Documentation and Template Rules

Where possible, content should be supported by templates and documented standards.

Useful template areas include:

- product title patterns
- product description patterns
- category intro patterns
- store bio patterns
- editorial article patterns

Templates should improve quality and consistency, not produce obvious sameness.

## Things Claude Must Not Do

Do not:

- write spammy marketplace copy
- invent facts about products or sellers
- use keyword stuffing
- generate filler text only for SEO length
- allow conflicting product attribute and prose content
- make unsupported claims sound factual
- create robotic AI-looking copy at scale
- let placeholder text leak into production
- expose internal moderation or admin-only notes publicly
- confuse brand tone across content surfaces
